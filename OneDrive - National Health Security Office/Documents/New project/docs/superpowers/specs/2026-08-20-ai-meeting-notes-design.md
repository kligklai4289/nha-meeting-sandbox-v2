# แบบผลิตภัณฑ์ระบบ AI Meeting Notes ภาษาไทยสำหรับองค์กร

วันที่: 20 สิงหาคม 2569  
สถานะ: รอผู้ใช้ตรวจรับเอกสารออกแบบ  
แพลตฟอร์ม: Android สำหรับผู้ใช้ และเว็บสำหรับผู้ดูแลระบบ

## 1. เป้าหมาย

สร้างระบบบันทึกการประชุมภาษาไทยที่สามารถ:

1. บันทึกเสียงต่อเนื่องสูงสุด 8 ชั่วโมงต่อรายการ
2. ถอดเสียงภาษาไทย แยกผู้พูด และแสดงเวลาอ้างอิง
3. สรุปประเด็นสำคัญและสร้างรายการสิ่งที่ต้องทำ
4. แชตถามตอบจากเนื้อหาการประชุมย้อนหลังพร้อมหลักฐานอ้างอิง
5. ใช้ Google Sign-in ได้กับบัญชี Google ทุกโดเมน
6. แยกข้อมูลของแต่ละองค์กรและบังคับมาตรการรองรับ PDPA ภายในระบบ

ผลลัพธ์รุ่นแรกต้องช่วยให้ผู้ใช้บันทึก ตรวจแก้ ค้นหา และนำผลการประชุมไปใช้งานได้ โดยไม่ต้องส่งไฟล์เสียงหรือข้อความผ่านช่องทางสาธารณะ

## 3. ผู้ใช้และบทบาท

### ผู้ใช้ทั่วไป

- มีพื้นที่ส่วนตัวหลังเข้าสู่ระบบด้วย Google
- สร้างและบันทึกการประชุม
- ตรวจแก้ ส่งออก และลบข้อมูลของตนเอง
- ขอเข้าร่วมองค์กรหรือเข้าร่วมผ่านคำเชิญ

### สมาชิกองค์กร

- เข้าถึงเฉพาะการประชุมที่ได้รับสิทธิ์
- สร้างบันทึกในพื้นที่องค์กรตามนโยบายขององค์กร
- แชร์ให้สมาชิกที่ได้รับอนุญาตเท่านั้น

### ผู้ตรวจทาน

- ตรวจและยืนยันข้อความ ผู้พูด สรุป มติ และรายการงาน
- ไม่สามารถเปลี่ยนนโยบายความปลอดภัยหรืออายุข้อมูล

### ผู้ดูแลระบบองค์กร

- อนุมัติและระงับสมาชิก
- กำหนดบทบาทและสิทธิ์
- ดู Audit Log และจัดการคำขอใช้สิทธิ
- เปิด Incident Workflow และระงับการแชร์
- ต้องใช้ MFA

## 4. การยืนยันตัวตนและการเข้าร่วมองค์กร

1. ผู้ใช้เลือก `เข้าสู่ระบบด้วย Google`
2. แอปรับผลการยืนยันตัวตนและส่งโทเคนไปตรวจที่ Backend
3. Backend ตรวจลายเซ็น อัลกอริทึม issuer, audience, เวลาหมดอายุ และ nonce ตามช่องทางที่ใช้
4. ระบบสร้างบัญชีเมื่อเข้าสู่ระบบครั้งแรก โดยไม่เก็บรหัสผ่าน Google
5. ทุกบัญชี Google ใช้พื้นที่ส่วนตัวได้
6. การเข้าพื้นที่องค์กรต้องมาจากคำเชิญหรือได้รับอนุมัติจากผู้ดูแล
7. ผู้ใช้หนึ่งคนอยู่ได้หลายองค์กร แต่ข้อมูล สิทธิ์ คีย์ และ Audit Log ต้องแยกตามองค์กร
8. การซ่อนปุ่มในหน้าจอเป็นเพียง UX; Backend ต้องตรวจสิทธิ์ทุกคำขอและทุกรายการ

## 5. เส้นทางผู้ใช้หลัก

### 5.1 เริ่มบันทึก

1. ผู้ใช้เลือกพื้นที่ส่วนตัวหรือองค์กร
2. ระบุชื่อการประชุม วัตถุประสงค์ ฐานการประมวลผล และผู้เข้าร่วมเท่าที่จำเป็น
3. ระบบแสดง Privacy Notice ฉบับที่ใช้อยู่
4. ผู้ใช้ยืนยันว่าได้แจ้งผู้เข้าร่วมแล้ว ระบบเก็บวันเวลาและเวอร์ชันข้อความ
5. ระบบตรวจสิทธิ์ไมโครโฟน พื้นที่ว่าง แบตเตอรี่ และข้อจำกัดเครื่อง
6. ปุ่ม `เริ่มบันทึก` จึงเปิดใช้งาน

### 5.2 ระหว่างบันทึก

- แสดงเวลารวม สถานะไมโครโฟน เครือข่าย พื้นที่ว่าง และการอัปโหลด
- รองรับหยุดชั่วคราว ทำต่อ และทำเครื่องหมายช่วงสำคัญ
- บันทึกเป็นเสียง mono แบบ AAC-LC ที่ 16 kHz และ 32–48 kbps เป็นค่าเริ่มต้น โดยประมาณการพื้นที่ 115–173 MB สำหรับ 8 ชั่วโมง; อุปกรณ์ที่ไม่รองรับต้องใช้รูปแบบ fallback ที่ Backend แปลงได้
- แบ่งไฟล์ภายในช่วงละ 10 นาที โดยผู้ใช้เห็นเป็นรายการเดียว
- เข้ารหัสและปิดไฟล์แต่ละช่วงทันที
- อัปโหลดส่วนที่ปิดแล้วเมื่อเครือข่ายพร้อม และทำต่อจากจุดค้างได้
- แจ้งเตือนก่อนครบ 8 ชั่วโมงที่ 30 นาทีและ 10 นาที
- หยุดและบันทึกอย่างปลอดภัยเมื่อครบ 8 ชั่วโมง

### 5.3 หลังบันทึก

1. ระบบตรวจจำนวนชิ้นไฟล์และ checksum
2. Queue ส่งงานถอดเสียง แยกผู้พูด สรุป สกัดรายการงาน และสร้างดัชนีแชต
3. ผู้ใช้เห็นสถานะ `รออัปโหลด`, `กำลังถอดเสียง`, `กำลังสรุป`, `พร้อมตรวจ`, `ผิดพลาด` หรือ `กำลังลบ`
4. เมื่อพร้อม ผู้ใช้ตรวจแก้คำ ชื่อบุคคล และผู้พูดโดยกดฟังจากตำแหน่งเวลาได้
5. ผู้ตรวจทานยืนยันผลก่อนส่งออกหรือแชร์ หากองค์กรบังคับการตรวจทาน

### 5.4 ถาม AI

- ผู้ใช้ถามได้เฉพาะการประชุมที่ตนมีสิทธิ์
- ระบบค้นข้อความส่วนที่เกี่ยวข้องก่อนส่งให้โมเดล
- ทุกคำตอบต้องมีข้อความอ้างอิง ผู้พูด และตำแหน่งเวลา
- หากหลักฐานไม่เพียงพอ ระบบตอบว่าไม่พบข้อมูลแทนการคาดเดา
- เมื่อข้อมูลครบ 30 วัน ดัชนีและประวัติแชตที่มีเนื้อหาต้องถูกลบพร้อมกัน

## 6. หน้าจอ

### Android

1. `เข้าสู่ระบบ` — Google Sign-in และ Privacy Notice

3. `เตรียมบันทึก` — ชื่อ วัตถุประสงค์ ฐานการประมวลผล และการยืนยันแจ้งผู้เข้าร่วม
4. `กำลังบันทึก` — เวลา หยุดชั่วคราว ทำเครื่องหมาย สถานะเครื่องและเครือข่าย
5. `กำลังประมวลผล` — ขั้นตอน ความคืบหน้า และการกู้คืนข้อผิดพลาด
6. `ผลการประชุม` — สรุป มติ งาน ข้อความถอดเสียง และไฟล์
7. `ตรวจแก้ข้อความ` — เสียงตามเวลา คำที่ไม่มั่นใจ และชื่อผู้พูด
8. `ถาม AI` — คำถาม คำตอบ หลักฐาน และปุ่มไปยังเวลาในเสียง
9. `แชร์และส่งออก` — สมาชิกที่มีสิทธิ์ Word และ PDF
10. `ความเป็นส่วนตัว` — วันหมดอายุ ลบข้อมูล ถอนการแชร์ และส่งคำขอใช้สิทธิ

### เว็บผู้ดูแล

1. สมาชิก คำเชิญ การอนุมัติ และบทบาท
2. นโยบายองค์กรและ Privacy Notice
3. รายการประชุมและสถานะการลบ โดยไม่เปิดเนื้อหาเกินสิทธิ์
4. Audit Log
5. คำขอใช้สิทธิของเจ้าของข้อมูล
6. เหตุข้อมูลรั่วไหลและการระงับการแชร์
7. รายชื่อผู้ให้บริการ Cloud และผู้ประมวลผลช่วง

## 7. สถาปัตยกรรม

### แอปและเว็บ

- Android: Kotlin และ Jetpack Compose
- เว็บผู้ดูแล: React และ TypeScript
- Backend API: Python และ FastAPI
- ฐานข้อมูล: PostgreSQL
- ไฟล์เสียง: Object Storage ที่รองรับ encryption at rest และ lifecycle deletion
- งานเบื้องหลัง: Queue และ Worker แบบ idempotent

### บริการ Backend

- Identity Service — Google Sign-in, session และบทบาท
- Organization Service — สมาชิก คำเชิญ และนโยบาย
- Recording Service — metadata, upload session, checksum และช่วงเสียง
- AI Orchestrator — ถอดเสียง แยกผู้พูด สรุป สกัดงาน และดัชนี
- Meeting Service — ข้อความ สรุป งาน การตรวจทาน และส่งออก
- Chat Service — retrieval, policy และ citation validation
- Privacy Service — notice, lawful basis, retention และคำขอใช้สิทธิ
- Audit Service — append-only events
- Incident Service — ระงับการแชร์ หลักฐาน และลำดับการรับมือเหตุ
- Deletion Service — ลบข้อมูลทุกที่แบบติดตามสถานะและทำซ้ำได้

### การไหลของข้อมูล

`Android → encrypted chunk upload → object storage → queue → speech-to-text/diarization → transcript → summary/actions → search index → cited chat`

AI Gateway ต้องซ่อนรายละเอียดผู้ให้บริการภายนอกหลัง interface เดียว เพื่อเปลี่ยนผู้ให้บริการได้โดยไม่เปลี่ยนข้อมูลหรือหน้าจอหลัก และต้องบังคับนโยบายห้ามฝึกโมเดลด้วยข้อมูลลูกค้า

## 8. แบบข้อมูลหลัก

- `users` — Google subject, email, display name, status
- `organizations` — ชื่อ นโยบาย และคีย์อ้างอิง
- `memberships` — ผู้ใช้ องค์กร บทบาท และสถานะอนุมัติ
- `meetings` — เจ้าของ องค์กร ชื่อ วัตถุประสงค์ ฐานประมวลผล สถานะ และวันลบ
- `recording_chunks` — ลำดับ checksum ระยะเวลา สถานะอัปโหลด และ storage key แบบ opaque
- `speakers` — ป้ายผู้พูดและชื่อที่ผู้ใช้ยืนยัน
- `transcript_segments` — เวลาเริ่ม/จบ ผู้พูด ข้อความ confidence และสถานะตรวจแก้
- `summaries` — สรุป มติ รุ่นโมเดล และวันลบ
- `action_items` — งาน ผู้รับผิดชอบ กำหนดส่ง หลักฐาน และสถานะ
- `chat_messages` — คำถาม คำตอบ citation และวันลบ
- `consent_notices` — เนื้อหา เวอร์ชัน และช่วงเวลาที่มีผล
- `notice_acknowledgements` — ผู้ยืนยัน การประชุม เวอร์ชัน และเวลา
- `audit_events` — ผู้กระทำ เหตุการณ์ resource UUID เวลา และผลลัพธ์ โดยไม่เก็บเนื้อหาประชุม
- `deletion_jobs` — ขอบเขต เป้าหมาย ความคืบหน้า retry และหลักฐานเสร็จสิ้น
- `incidents` — ประเภท เวลา ผลกระทบ สถานะ และหลักฐานการตอบสนอง

Public identifier ทุกชนิดใช้ UUID แบบสุ่ม ไม่ใช้เลขเรียงลำดับ

## 9. ความแม่นยำภาษาไทย

- เลือก Speech-to-Text ที่รองรับภาษาไทยและการแยกผู้พูด
- รองรับพจนานุกรมชื่อบุคคล หน่วยงาน คำย่อ และศัพท์เฉพาะขององค์กร
- เก็บ confidence ระดับช่วงหรือคำเมื่อผู้ให้บริการรองรับ
- ทำเครื่องหมายข้อความที่ไม่มั่นใจและเปิดเสียงตรงตำแหน่งนั้น
- ไม่เดาผู้พูดเมื่อเสียงซ้อนหรือหลักฐานไม่เพียงพอ
- สรุปจาก transcript ที่มีเวอร์ชันชัดเจน และสร้างสรุปใหม่เมื่อผู้ใช้แก้ข้อความสำคัญ
- เป้าหมายเสียงชัดคือความถูกต้อง 90–97% แต่ไม่รับประกัน 100%
- ชุดทดสอบต้องมีหลายสำเนียง เสียงรบกวน ศัพท์เฉพาะ ตัวเลข วันที่ และการพูดไทยสลับอังกฤษ

## 10. รายการสิ่งที่ต้องทำ

แต่ละรายการต้องมี:

- รายละเอียดงาน
- ผู้รับผิดชอบ หรือ `ยังไม่ระบุ`
- กำหนดส่ง หรือ `ยังไม่ระบุ`
- สถานะ
- ข้อความหลักฐาน
- ผู้พูด
- ตำแหน่งเวลาในเสียง
- สถานะว่าผู้ใช้ตรวจยืนยันแล้วหรือไม่

AI ห้ามสร้างชื่อผู้รับผิดชอบหรือกำหนดส่งเมื่อไม่มีหลักฐานชัดเจน

## 11. PDPA และความปลอดภัยที่บังคับในระบบ

ระบบไม่มีขั้นตอนรอ DPO หรือฝ่ายกฎหมายอนุมัติ แต่ข้อควบคุมต่อไปนี้ปิดไม่ได้:

- ห้ามเริ่มบันทึกก่อนระบุวัตถุประสงค์ ฐานประมวลผล และยืนยันการแจ้งผู้เข้าร่วม
- เก็บเวอร์ชัน Privacy Notice และหลักฐานการรับทราบ
- ไม่มี Public URL สำหรับเสียง ข้อความ หรือไฟล์ส่งออก
- ตรวจสิทธิ์ระดับองค์กร ระดับรายการ และระดับการกระทำที่ Backend
- ใช้หลัก deny-by-default และ least privilege
- เข้ารหัสระหว่างส่งและขณะจัดเก็บ พร้อมแยกคีย์ตามองค์กรเมื่อโครงสร้าง Cloud รองรับ
- ลิงก์ดาวน์โหลดเป็น signed URL อายุสั้นและผูกกับสิทธิ์
- ผู้ดูแลต้องผ่าน MFA แบบ TOTP หรือ WebAuthn ที่ระบบตรวจได้เองก่อนใช้สิทธิ์ผู้ดูแล โดยไม่สมมติว่าบัญชี Google เปิด MFA อยู่แล้ว และการกระทำสำคัญถูกบันทึก
- ไม่เก็บโทเคนระยะยาวใน Web Storage
- เว็บใช้ CSRF protection เมื่อ session อาศัย cookie
- จำกัด CORS, Host, proxy trust, request size, rate และชนิดไฟล์
- ปิด debug, reload, public OpenAPI และ stack trace ใน production
- ไม่ render HTML จากข้อความประชุม และใช้ CSP/security headers
- Cloud processor ต้องมีข้อตกลงประมวลผลข้อมูล รายชื่อ subprocessor นโยบายไม่ฝึกโมเดล และกระบวนการลบ
- การส่งข้อมูลต่างประเทศต้องถูกบันทึกในนโยบายและรายการกิจกรรมประมวลผล
- รองรับคำขอเข้าถึง สำเนา แก้ไข ลบ จำกัด คัดค้าน ถอนความยินยอม และโอนข้อมูลตามกรณี
- มี Incident Workflow และข้อมูลที่จำเป็นสำหรับการแจ้งเหตุภายใน 72 ชั่วโมงเมื่อเข้าเงื่อนไขตามกฎหมาย
- หากตรวจพบเนื้อหาอ่อนไหว ระบบเตือน จำกัดการแชร์ และเพิ่มชั้นยืนยัน

ระบบจะอธิบายตนเองว่า `ออกแบบให้รองรับการปฏิบัติตาม PDPA` และไม่แสดงข้อความรับรองว่าองค์กรสอดคล้องกฎหมายโดยอัตโนมัติ

## 12. อายุข้อมูลและการลบ

### ไฟล์เสียง: 7 วัน

- นับจากเวลาสิ้นสุดการบันทึก
- ผู้ใช้ลบก่อนกำหนดได้
- ลบไฟล์หลัก ชิ้นไฟล์ชั่วคราว สำเนาประมวลผล และสำเนาในอุปกรณ์
- ข้อมูลที่รอลบต้องถูกปิดการเข้าถึงทันที
- งานที่ยังประมวลผลไม่เสร็จเมื่อครบกำหนดต้องถูกยกเลิกและลบ

### Transcript, summary, action items, chat และดัชนี: 30 วัน

- นับจากเวลาสิ้นสุดการบันทึก
- ลบข้อมูลหลัก แคช ดัชนี search/vector และไฟล์ส่งออกที่ระบบจัดเก็บ
- หลังลบ Chat Service ต้องไม่สามารถตอบจากเนื้อหานั้นได้

### Audit Log: 1 ปี

- เก็บ metadata ของเหตุการณ์เท่านั้น
- ห้ามเก็บข้อความถอดเสียง สรุป เนื้อหาแชต หรือเสียง
- เมื่อครบกำหนดให้ลบหรือทำให้ไม่สามารถระบุตัวบุคคลตามนโยบายที่กำหนด

Deletion Service ต้องทำงานแบบ idempotent มี retry, dead-letter handling, reconciliation รายวัน และหลักฐานผลการลบที่ไม่บรรจุเนื้อหาต้นฉบับ

## 13. การจัดการข้อผิดพลาด

- อินเทอร์เน็ตหลุด: บันทึกต่อในเครื่องและอัปโหลดต่อจากชิ้นที่ค้าง
- แอปถูกปิด: กู้คืน manifest และชิ้นเสียงที่ปิดสมบูรณ์แล้ว
- พื้นที่ไม่พอ: เตือนล่วงหน้าและหยุดอย่างปลอดภัยก่อนเขียนไฟล์ล้มเหลว
- แบตเตอรี่ต่ำหรือเครื่องร้อน: เตือนและแนะนำการแก้ไขโดยไม่ทำข้อมูลหาย
- สิทธิ์ไมโครโฟนถูกปฏิเสธ: อธิบายและพาไปหน้าตั้งค่าเมื่อผู้ใช้เลือก
- ถอดเสียงล้มเหลว: retry จำกัดจำนวนครั้งและไม่ขยายอายุข้อมูล
- พูดซ้อน: ใช้ `ไม่ทราบผู้พูด` แทนการเดา
- AI ไม่มีหลักฐาน: ปฏิเสธการตอบหรือเว้นค่าฟิลด์
- ลบบางระบบล้มเหลว: ปิดการเข้าถึงทันที retry และแจ้งผู้ดูแล
- Google token ผิดปกติ: ปฏิเสธการสร้าง session
- การเข้าถึงข้ามองค์กร: ตอบแบบไม่เปิดเผยว่ารายการนั้นมีอยู่

## 14. คู่มือใช้งานฉบับย่อ

1. เปิดแอปและเลือก `เข้าสู่ระบบด้วย Google`
2. เลือกพื้นที่ส่วนตัวหรือองค์กรที่ได้รับอนุมัติ
3. กด `บันทึกใหม่` และกรอกชื่อกับวัตถุประสงค์
4. อ่าน Privacy Notice และยืนยันว่าได้แจ้งผู้เข้าร่วมแล้ว
5. กด `เริ่มบันทึก`; ใช้ `หยุดชั่วคราว` หรือ `ทำเครื่องหมาย` ได้ระหว่างประชุม
6. กด `จบการบันทึก`; รอระบบอัปโหลด ถอดเสียง และสรุป
7. เปิด `พร้อมตรวจ` แล้วแก้คำหรือชื่อผู้พูดโดยกดฟังจากเวลาอ้างอิง
8. ตรวจสรุป มติ และรายการงานก่อนยืนยัน
9. เปิด `ถาม AI` และตรวจหลักฐานใต้คำตอบทุกครั้ง
10. ส่งออก Word/PDF หรือแชร์เฉพาะสมาชิกที่ได้รับสิทธิ์
11. ตรวจวันหมดอายุในหน้า `ความเป็นส่วนตัว` หรือลบก่อนกำหนดได้

## 16. เกณฑ์รับรุ่นแรก

- บันทึก 8 ชั่วโมงผ่านหลายรอบบนอุปกรณ์เป้าหมายอย่างน้อยระดับล่าง กลาง และสูง
- ไม่มีช่วงเสียงซ้ำหรือขาดจากความผิดพลาดของระบบ; เหตุจาก OS หรือโทรศัพท์ต้องถูกตรวจพบและแจ้ง
- อัปโหลดต่อได้หลังเครือข่ายกลับมาโดยไม่เริ่มใหม่
- ผู้ใช้ข้ามองค์กรเข้าถึงข้อมูลไม่ได้ทุกเส้นทาง API
- คำตอบ AI และรายการงานผ่าน citation validation
- งานลบวันที่ 7 และ 30 ผ่านการทดสอบแบบเร่งเวลา รวมถึง storage, database, cache, index และ backup lifecycle
- Audit Log ไม่มีเนื้อหาการประชุม
- Production ไม่มี public object, debug trace, public API docs หรือ permissive CORS
- คู่มือใช้งานและข้อความแจ้งข้อผิดพลาดเป็นภาษาไทยที่ผู้ใช้ทั่วไปเข้าใจได้

## 17. ตัวชี้วัดหลังเปิดใช้

- อัตราบันทึกสำเร็จและกู้คืนสำเร็จ
- สัดส่วนชิ้นเสียงที่อัปโหลดสำเร็จครั้งแรกและหลัง retry
- เวลาตั้งแต่จบบันทึกจนผลพร้อมตรวจ
- อัตราคำที่ผู้ใช้แก้และอัตราการแก้ชื่อเฉพาะ
- สัดส่วนคำตอบแชตที่มี citation ผ่าน validator
- อัตรารายการงานที่ผู้ใช้ยืนยันหรือแก้ไข
- จำนวนการปฏิเสธสิทธิ์ข้ามองค์กร
- อัตรางานลบเสร็จภายใน SLA
- เหตุข้อมูลรั่วไหลและเวลาตรวจพบ/ระงับ
